# Problem And Method Blueprint — 把粗方向磨成 problem + method

## 磨问题

强问题陈述要回答：

```text
任务或现象是什么？
目标社区里谁在乎？
最强已有工作之后还剩什么 gap？
为什么这个 gap 难，而不只是没人做？
解决后会变得可能的是什么？
什么边界防止过度声称？
```

好问题通常有以下至少一条性质：

- 暴露了强已有工作处理不了的瓶颈。
- 定义了一个改变技术需求的新设定。
- 揭示了常见假设与真实使用之间的错配。
- 用一种产生新能力或新问题的方式连接了两个领域。
- 把一个隐藏的评测 gap 变得可测量。

## 磨机制

把方法名翻译成机制：

```text
输入与输出:
关键表示:
主操作:
优化或推理目标:
为什么这个机制能打中 root challenge:
假设:
失败模式:
被否决的替代设计:
```

若方法是已知组件的组合，找出**非平凡的交互点**。没有交互点就是工程拼装，需要更尖的贡献或更强的 benchmark/证据故事。

## 贡献类型

挑最强的诚实贡献（最多 1-2 个，别全认领）：

- 新问题 / 新设定
- 新方法 / 新架构
- 新目标 / 新推理过程 / 新理论结果
- 新数据集 / benchmark / 负载 / 协议
- 新系统设计 / 部署洞见
- 新实证发现 / 诊断分析
- 化解已知张力的新综合

## 优雅性检查

优雅的 idea 通常：

- 有一个能解释整个方法的中心洞见。
- 方法的每个部分都是必要的，不是装饰。
- claim 简单到能被直接验证。
- 失败模式可理解。
- 即使 SOTA 提升不大，结果也能教给社区一点东西。

## 致命 idea 风险（早标）

- 新颖性在某篇大概率存在的近邻工作下坍塌。
- 问题对目标场景太窄。
- 方法是换了术语的已知 trick。
- 核心 claim 用现有资源无法验证。
- 证据需要一个时间内造不出的数据集 / 证明 / 系统。
- idea 依赖审稿人会拒绝的隐藏假设。
