# Experiment Design — 最小说服性证据包

## 证据原则

设计实验是为了回答 reviewer 的那句"证据测到核心 claim 了吗？"。不为凑量加实验。每个实验都要在防守某一项：新颖性 / 可靠性 / 重要性 / 泛化 / 效率 / 边界。

## 实验矩阵

每个主 claim 建一行：

```text
Claim:
需要的证据:
数据集 / benchmark / 负载 / 证明 / 用户研究:
Baselines:
指标:
Ablations:
压力 / 鲁棒性测试:
失败分析:
回应的 reviewer 疑问:
```

## Baseline 规则

- 可行时纳入最强的近邻已有工作。
- 区分复现的 baseline、文献报告数、不可比设定。
- 跑不了的 baseline 要解释为什么。
- 不做不公平改编、额外数据、隐藏调参优势。
- 加简单 baseline，测核心机制是不是必要。

## Ablation 规则

用 ablation 测机制，不只是测掉点：

- 逐个移除核心组件。
- 把提出的组件换成一个合理的通用替代。
- 扫关键超参 / 阈值。
- 展示方法什么时候失败。
- 数值指标掩盖行为时，补定性或诊断证据。

## 最小说服性证据包

1. 主结果 vs 近邻 baseline。
2. 机制 ablation，或为什么有效的证明。
3. 鲁棒性 / 泛化 / 压力测试。
4. 局限 / 失败分析。
5. 足以复核的可复现细节。

若在用户约束下造不出这个包，建议收窄 claim、换场景，或转向 idea。

## 按领域的证据侧重（按需）

- ML/AI：ablation、多 seed/统计、数据划分、鲁棒性、算力、scaling、诊断分析。
- CV：可视化对比、分类别/难例分析、公平的图像/视频设置、失败案例。
- NLP：数据质量、标注一致性、泄漏检查、人工/自动评测有效性、错误分类。
- DB/KDD/IR：规模、延迟、内存、吞吐、排序指标、负载真实性、部署约束。
- 系统：端到端评测、microbenchmark、开销、敏感性、资源使用、运行失败案例。
- 安全：威胁模型、绕过尝试、自适应攻击、保证、负责任披露、局限。
- HCI：被试招募、任务、测度、统计、定性编码、伦理、claim 边界。
- 理论：定理陈述、证明草图、例子、与已知结果的关系、假设的边界。
